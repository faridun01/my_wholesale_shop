# Аудит безопасности, производительности и доступности — 11.11.2026

Проверялась сборка из рабочей копии поверх коммита `35a4fb2` на локальном стенде:
Docker-образы backend и frontend, PostgreSQL 16 с копией реальных данных. Каждый вывод
ниже подтверждён запуском (тест, запрос, браузерный сценарий), а не только чтением кода.

## Архитектура и развёртывание

```text
Интернет → Caddy на VPS (TLS, crm.itforce.pro) → 127.0.0.1:8080
  → nginx (контейнер frontend: SPA, /assets, /api/ и /uploads/ проксирует)
    → Express (контейнер backend, Prisma) → PostgreSQL 16 (контейнер, только внутренняя сеть)
```

- **Frontend:** React 18, Vite 6, Tailwind 4.
- **Backend:** Express 4, Prisma 6.19.3, Node 22.
- **Сборка:** CI (GitHub Actions) прогоняет typecheck, ESLint, аудит зависимостей, тесты
  на PostgreSQL 16, сборку frontend, `docker compose build` и `nginx -t`. Затем
  публикует образы в GHCR с тегами `master` и `sha-<commit>`.
- **Обновление сервера:** вручную, по [DOCKER_DEPLOY.md](../DOCKER_DEPLOY.md).

## Найденные проблемы и что сделано

### Высокий приоритет

1. **Страница отдавалась без заголовков безопасности.** Причина: заголовки ставил только
   Express (`/api`), а HTML и статику отдаёт nginx. В nginx `add_header` внутри `location`
   отключает наследование заголовков уровня `server`.
   - Заголовки вынесены в `frontend/security-headers.conf` и подключены в каждый
     `location` (коммит `35a4fb2`).
   - Проверено curl-запросами к странице, ассетам, API и `robots.txt`.
2. **Обновление сервера могло положить сайт.** С `35a4fb2` backend не применяет миграции
   сам. При неприменённой миграции он завершался с ошибкой и вводящим в заблуждение
   советом Prisma, а значит уходил в цикл перезапусков. Прежняя инструкция по обновлению
   об этом не знала.
   - Остановка без явного разрешения сохранена: работать на старой схеме нельзя.
   - Добавлено понятное сообщение.
   - В `DOCKER_DEPLOY.md` описаны резервная копия → `APPLY_MIGRATIONS=true` → проверка → откат.
   - Проверено на пустой базе: без флага — код выхода 1 и инструкция; с флагом применены
     все 28 миграций и сервер запущен.
3. **Резервная копия могла быть пустой.**
   - `backup.sh` без `pipefail` сообщал «успешно» при упавшем `pg_dump`.
   - Скрипты и команда в документации использовали несуществующую базу `wholesale_shop`.
   - Исправлено: проверка ошибки, удаление пустого файла, имя `my_wholesale_shop`,
     формат `-Fc` и команда восстановления.
4. **Учётная запись покупателя (портал) имела доступ к API сотрудников.**
   - Подтверждено запросами: покупатель создал клиента (`POST /customers` → 201) и
     напоминание. Накладную не создал только потому, что у его учётной записи не было
     склада.
   - Добавлен `staffOnly` на группы маршрутов сотрудников и на загрузку файлов.
   - После исправления: 23 чтения и 13 записей → 403; товары, склады и заказы портала
     доступны (200).
5. **Загруженные фото товаров не показывались.** Frontend строит адрес `/api/uploads/…`, а
   backend отдавал файлы только по `/uploads/…` → 404. Вместо фото подставлялась случайная
   картинка с picsum.photos.
   - Добавлен маршрут `/api/uploads` с той же авторизацией и приватным кэшем.
   - Проверено загрузкой: было 404, стало 200 `image/png`.
6. **Уязвимые зависимости.**
   - Backend: `compression` (утечка памяти при обрыве соединения, а SSE обрывается
     постоянно), `body-parser`, `proxy-addr` (critical), `sharp`, `qs`, `express`.
   - Frontend: `dompurify` (critical), `follow-redirects`, `fflate`.
   - Обновлено в пределах мажорных версий.
   - Сохранено: Prisma CLI остаётся в рантайм-зависимостях. npm пытался перенести его в
     devDependencies, и тогда миграции в образе перестали бы работать.

### Средний приоритет

7. **HSTS был сокращён до `max-age=300`** в коммите `35a4fb2`. API и раньше отдавал
   `max-age=31536000; includeSubDomains`, то есть браузеры уже держали годовую политику, и
   короткое значение её ослабляло. Возвращено одинаковое годовое значение в nginx и
   Express. `preload` не включался.
8. **CSP.**
   - Политика работает в режиме Report-Only с отправкой отчётов на `/api/security/csp-report`.
   - Шрифты перенесены с Google Fonts на свой сервер, поэтому из политики убраны
     внешние хосты.
   - Из шаблонов печати убраны inline-скрипты: под строгой CSP они бы не выполнились.
     Печать вызывается из кода приложения.
   - Браузерная проверка 21 экрана (админ, компьютер; продавец, телефон): **0 нарушений**.
9. **Шрифты блокировали отрисовку.** Google Fonts CSS блокировал первую отрисовку
   (оценка Lighthouse — около 300 мс) и требовал соединений с двумя внешними доменами.
   Теперь Inter и JetBrains Mono отдаются со своего домена (`@fontsource-variable`), а
   браузер скачивает только нужные наборы символов.
10. **Доступность (axe, WCAG 2.1 A/AA, 21 экран).**
    - Было: около 420 нарушений, из них критичные — поля и списки без подписи, кнопки-иконки
      без названия, диаграммы без альтернативы.
    - Стало: 0 критичных, 16 некритичных элементов контраста.
    - Цвета `slate-400/500` и статусные `emerald`, `amber`, `rose` в теме затемнены ровно
      до 4,5:1 на всех светлых фонах приложения.
    - Единственное место на тёмном фоне переведено на светлый оттенок; это проверено
      измерением в браузере.
11. **Страница входа.**
    - Кнопка «показать пароль» без названия и слишком маленькая.
    - Подписи не связаны с полями.
    - Нет `autocomplete`, поэтому менеджеры паролей и мобильные клавиатуры не
      подставляли логин и пароль.
12. **SEO.**
    - Не было `meta description` — добавлено.
    - Не было `robots.txt`: nginx отдавал вместо него HTML, отсюда 36 ошибок. Добавлен
      `robots.txt` с `Disallow: /`: это закрытая CRM, и её страницам не место в поиске.

### Низкий приоритет

13. Двойной `Cache-Control` на `/assets` (`expires` + `add_header`) — убран дубль.
14. Админская оплата без накладной с некорректным `customer_id` отвечала 500 вместо 400.
15. В CI добавлены ESLint frontend и `npm audit --audit-level=critical` для
    production-зависимостей.
16. Файлы `docs/*-dependency-audit.json` содержали только сетевую ошибку — заменены
    реальными результатами.

## Проверено и признано корректным

- **Сессии.** JWT в cookie `httpOnly`, `Secure`, `SameSite=Lax`, срок 8 ч. На каждом
  запросе проверяется, что учётная запись активна (кэш 60 с).
- **CSRF.** Для изменяющих запросов проверяются `Origin` и `Referer`. Запрос с cookie без
  них отклоняется — это подтвердили пробные скрипты.
- **Права ролей.** Изменяющие маршруты проверяют роль или склад: товары, склады,
  настройки, отмена оплат, выдача денег и подтверждение кассы — только администратор.
- **Финансы.**
  - Ключи идемпотентности с advisory-блокировкой.
  - Блокировка накладной `FOR UPDATE`, запрет переплаты.
  - Append-only журналы с триггерами в БД и журнал аудита.
  - Покрыто 182 тестами, включая конкурентные сценарии.
- **API и индексы.** Время ответа на копии реальных данных: основные списки 3–45 мс,
  отчёты за 10 месяцев 0,3–0,5 с. Нужные индексы есть, в том числе по `user_id` и
  `reversal_of_id` оплат.

## Оставшиеся риски

- **CSP не включена в принудительном режиме.** После нескольких дней без отчётов в логах
  backend (`CSP report`) включить её одной строкой: заменить
  `Content-Security-Policy-Report-Only` на `Content-Security-Policy` в
  `frontend/security-headers.conf`. `style-src 'unsafe-inline'` остаётся из-за React
  style-атрибутов и библиотеки уведомлений.
- **Уязвимости, которые устраняются только мажорными обновлениями.**
  - Prisma 7 (high): затрагивает CLI миграций, а не обработку запросов.
  - Zod 4 (high): исчерпание памяти при валидации больших коллекций; тело запроса
    ограничено 10 МБ.
  - Обе требуют отдельной миграции кода.
- **Отчёты за большие периоды (0,3–0,5 с) читают строки в память.** Перевод на SQL-агрегации
  рискован для точности FIFO и скидок (см. PERFORMANCE_AUDIT_2026-11-09).
- **Сессию нельзя отозвать до истечения 8 часов**, например при смене пароля. Частично это
  смягчает проверка активности учётной записи.
- **Мелкое.** 16 некритичных нарушений контраста: прочерки `text-slate-300` и подписи в
  тёмных подсказках. `img-src` допускает `https:` из-за заглушек picsum.photos.
