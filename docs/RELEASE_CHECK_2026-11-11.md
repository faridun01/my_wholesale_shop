## Что может остановить обновление

**Неприменённые миграции.** Теперь backend по умолчанию проверяет схему и
останавливается, если ей нужны миграции. Поэтому обычная замена образов без
подготовки может временно сделать API недоступным. Это проверено, а не предположение.
Порядок обновления с явным разрешением — в [DOCKER_DEPLOY.md](../DOCKER_DEPLOY.md).

Нужны свежая проверенная резервная копия, репетиция именно на копии актуальной
серверной базы, согласованное применение миграций и проверка HTTPS после обновления.
Тест пустой БД не доказывает совместимость всех старых записей серверной базы.

Откат образов по `sha-<commit>` не равен откату БД. Совместимость прежнего кода
с новой схемой нужно проверять отдельно; нельзя считать все имеющиеся миграции
только добавляющими данные: есть историческая корректировка
`20261109000500_reconcile_historical_records`. Восстановление backup может потерять
операции после его создания и не должно выполняться автоматически.
